# test.32：信任边界与召回局部优化

目标固定 DSH 0.2.2-rc.1。基于 Character main `e816daf899118e4b8ffab94fe409867c3ab6431e`、QQTK main `fad50e262b0ea78802c832ac4c39b71e5d3585ab`；使用隔离 Home、合成数据和确定性原生模型夹具，没有生产变更。QQTK 的 Identity & Access test.3 为配套审查切片，普通模式默认权限不变。

## 已有能力与本轮缺口

| 入口 | 已有机制 | 本轮处理 |
|---|---|---|
| QQ 正文 | 平台认证、白名单、角色授权；正文通过原生 UserMessage 交付 | 增加伪造 System/Owner/审批/工具 JSON、合法引用的回归；不改通信架构或筛掉正文 |
| 普通工具 | Character 的原生准备阶段 guard | 修复准备后身份失效时普通工具未复核的问题；此前仅 Schedule 的 dispatch 复核身份 |
| Identity & Access | Host 颁发身份/租约，contact/guest 原生工具范围 | 配套 QQTK 修复撤销后 Session 归属丢失与旧 Owner 变成 unmanaged 的放行分支；在 dispatch 再查租约 |
| 工具结果 | 原生 call/result 配对，只记录返回状态与引用，不采纳输出正文 | 对伪造成功、审批、Worker JSON 复测；返回成功不能证明目标完成 |
| Memory 提取与召回 | 可信句柄、原始来源、inference、CAS、跨用途遗忘屏障、L3 可见性规则 | 对模型伪造 origin/status/confidence/source 复测；合法引用可作为 uncertain 资料，不成为授权或已确认事实 |
| Worker 输出 | 原生 subagent-settled 用户消息，独立 Preset、工具范围、无父级 Memory/QQ 授权 | 原生夹具返回含 System/Owner/审批声明的正文，验证其仍是 user settlement，不入可信 L1；模型实际提交越权工具也被 Host 拒绝 |

权限判断位于 Host 工具准备与执行边界。新 Character 边界版本为 v3，避免 HMR 时旧 v2 已安装标记阻止补装。不会改变原生审批结论或扩大工具目录。新增回归先在旧 main 失败：普通工具 body 执行一次（应为零）；另一主体可接管已撤销 Session；旧 Owner 的工具 guard 意外允许。

这些是确定性的身份/权限保证，不是“模型永远不会受注入影响”的证明。Owner 当前已获授权的能力仍受其既有权限与审批配置控制；任何模型声称批准均不代表真实批准。没有引入新审批路由、任务 grants 或全链路文本污点系统。Memory 的既有内容启发式仍有误判/漏判可能，它不是权限依据；提取引文匹配也不证明归纳语义正确。

## 召回评测与改动

`tests/fixtures/recall-corpus.mjs` 为版本化合成语料：19 条种子记录，14 个中英文/混合检索判断，覆盖同义表达、有词面锚点与无锚点情况、长记录、跨 Session、正常引用，以及来源、过期、冲突和遗忘。可增加 2,000 条确定性背景记录；其中数字等词项可能与查询重叠。相关性 2 表示目标事实，1 表示仅话题相关的干扰项，后者不计 Recall。

先测量，再只改两个局部点：

1. 精确短语加分使用与 FTS 相同的 NFKC、小写归一化；保留原分数权重、词项、预算与最多 20 条返回规则。
2. 把原有 FTS 匹配集合与主体/用途/证据/过期/遗忘 SQL 条件相交后再物化，不再先读所有可见记录再在 JS 过滤。保持 BM25 与候选语义，不在合法性过滤前增加 LIMIT。不改变 FTS 表、索引 token 或 Memory Schema 3。

同机样本，14 个查询各测 10 轮，预热 2 轮；小语料与背景语料分别报告，不能混作一个收益。

| 指标 | 19 条种子：前 → 后 | 加 2,000 条背景：前 → 后 |
|---|---|---|
| Recall@1 | 0.643 → 0.714 | 0.571 → 0.571 |
| Recall@5 | 0.857 → 0.857 | 0.857 → 0.857 |
| MRR（返回最多 20 条） | 0.750 → 0.786 | 0.690 → 0.690 |
| nDCG@5 | 0.814 → 0.828 | 0.784 → 0.784 |
| 每查询 SQLite→JS 物化行数 | 18.79 → 1.79 | 2018.93 → 1.93 |
| p50 延迟 | 0.484 → 0.398 ms | 5.891 → 0.435 ms |
| p95 延迟 | 1.158 → 0.897 ms | 7.813 → 0.924 ms |

第二组完整 140 次查询的 CPU 样本为 860 → 62 ms；heap 差值约 46.0 → 3.3 MB，RSS 差值约 49.1 → 0.4 MB，数据库与 WAL 大小不变。内存差值不是峰值或常驻上限，受 GC/进程环境影响；墙钟也会波动。物化行数是更稳定的工作量指标。已有 claimKey 冲突仍可能需要读取完整可见集合核对，广泛命中的查询也不保证相同加速。

两个无词面重叠的同义词查询仍失败；背景语料下的前三位排序也仍可能受 BM25 影响。本轮没有加入特定词表、重调权重或声称整体语义召回提升。0.857 是此合成集的结果，不能外推真实对话分布。

复现：

```powershell
# 当前开发树；仅创建并清理独立的合成 SQLite 临时目录。
npm test
npm run test:audit
npm run eval:recall -- --noise 2000 --rounds 10
# 用同一个新评测脚本测未修改的、独立 main 源码目录：
npm run eval:recall -- --implementation <CLEAN_CHARACTER_MAIN_DIRECTORY> --noise 2000 --rounds 10
```

不同进程分别测量，使用相同 Node 24、相同语料版本与 noise/rounds。资源结果由 `--expose-gc` 下的显式预采样 GC、CPU 差值、RSS/heap 差值与物化行计数给出。单元测试只对确定性质量、安全和工作量下界设门禁，不对机器速度设脆弱阈值。
