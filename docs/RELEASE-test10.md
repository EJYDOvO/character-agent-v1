# test.10：Interaction Policy V1

本机 DSH 仍为官方 0.2.1-rc.2，未修改发行文件。Character test.10、Interaction 0.1.0-test.1、Remote Ops 1.1.1-test.1 与 QQ Bot 0.5.2 新版本化补丁配套部署。数据库仍为 Schema 3，无数据迁移。原角色、Character 人格化模式、Session 和单 Owner 私聊策略保留。

## 变更和管理

交互策略在独立 Agent-scoped 插件中实现，QQTK 只适配 Sender、Streaming 和明确修正；Character Identity 复用可信入站。Remote Ops 保留维护与完成通知，让出普通等待提示。详细契约见 [Interaction](INTERACTION-POLICY.md)。

源码默认不启用。本机私有构建配置显式启用 Interaction，等待阈值 12 秒，配置了符合角色的固定等待文案。关闭须重新构建并进行配套部署，不是删除历史消息；仍要保持运行中工具的安全边界。

打包和源摘要可通过 `DSH_QQTK_PROJECT` 指向独立 QQTK 源码，避免误用安装目录的旧源码；未指定时保持旧维护入口。不可变包、锁文件、Profile 和 QQ 补丁需一起审查。当前发布不把本机私有角色或生产生成的 Core 上传 GitHub。

## 备份和恢复

在维护锁和空闲门禁下离线备份 Profile、Session、存储、QQ 状态、Character 数据、桌面配置、维护策略和 QQ 补丁，并逐文件核对。成功部署前的快照共 1803 个文件，包含 SQLite WAL；仅保存在本机受控维护目录。

首次切换时新宿主和 QQ 实际就绪，但部署脚本读取正在写入的日志遇到 Windows 共享模式限制，门禁触发回退。该日志问题也影响脚本内的恢复判定；随后独立核对确认 test.9、空闲状态及唯一 QQ ready 正常。修正日志读取方式后再次部署成功，保留首次失败与独立恢复证据。

回滚必须停止当前宿主，先保留新状态，再配套恢复旧 Profile/维护策略/QQ 补丁和离线快照，确认旧版本及新启动健康。恢复快照会回到快照时间点；不要把 Schema 未变化理解成自动合并新版记忆。官方 DSH 无需降级。

最终维护核对还发现旧 Profile 留有 test.8 的产物清单，以及安装目录下未同步的 QQ 维护源码。已先备份，再以本次逐文件验证及不可变包哈希重建 8 个产物登记、同步 4 个自有维护文件，`ops verify` 通过。候选准备脚本现在重新生成清单，另一个未启动候选的 8 个登记已校验；回滚时也应恢复配套维护源码，并按实际旧包核对登记，不能复用过期清单。

## 验收边界

启动、Session 恢复和 SDK 测试不代表手机已收件；本次另有用户确认正常气泡、无重复。真实 QQ 的逐帧时序、频控/异常网络、审批按钮仍未专项验收。没有将替身测试当成真实投递证明。Web 额外气泡/状态 UI、热卸载、断网恢复和高并发仍未端到端验收。确定性分段不等同于模型语义理解，取消也不能撤销工具副作用。
